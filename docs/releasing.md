# Releasing Fibbies

1. Fetch the public app repository and compare `main` to the latest GitHub release tag. Use the changes to choose the version bump and draft release notes. Increment Android's `versionCode` and update `versionName`, both npm version entries in the lockfile, `package.json`, and the fallback cache version in `sw.js`.
2. Add localized `fastlane/metadata/android/<locale>/changelogs/<versionCode>.txt` files for the seven store locales. Each changelog has a 500-character limit. Review the store descriptions, GitHub README and Juringari project page when the features they describe change.
3. Refresh screenshots when visible screens, translations or the logo change. From the Juringari checkout, run `npm run screenshots:fibbies` once the matching app code is live. It captures all seven languages. Review the captures and refresh the existing README images where needed. Then run `node scripts/sync-fibbies-store-images.mjs <path-to-fibbies>` from Juringari to carry the localized screenshots and the current icon into Fastlane. Commit the store files with the app release so F-Droid reads them from its tag.
4. Run `npm test`, `npm run sync`, and `node scripts/gradle.mjs :app:assembleRelease` with JDK 21 and Android SDK 36. Align and sign the APK locally using the existing Fibbies release key. Verify its package ID, version, signing certificate against the previous release, and SHA-256. Publish it as `Fibbies-v<version>.apk` in a GitHub release tagged `v<version>`. Check the public download and tag. Keep the signing key and password on the release machine.
5. After F-Droid accepts the app, verify that it has detected the tagged version, then confirm the build and listing when its publish cycle finishes. If it is still pending, report that separately from the verified GitHub release.

## F-Droid onboarding

- The listing comes from `fastlane/metadata/android/` on the release tag. The existing APK package ID is `io.github.slovenec88.fibbies`.
- For a source build using Android's text-to-speech engine, set `FIBBIES_NO_VOICE=1` during `npm run sync`. This omits the prerecorded Azure audio. Include `voice/` in the recipe's source removals for this build. Use `npm ci` with the lockfile, JDK 21, and the Android Gradle release task. Validate the recipe with the F-Droid build server and scanner before submission. A build with Android's voice engine differs from an APK that bundles recordings.
- To let users update between GitHub and F-Droid, publish the same variant on both channels and validate a reproducible rebuild with the existing developer certificate. A local Gradle build alone does not establish reproducibility. F-Droid's default signature would require users to reinstall when switching from the GitHub APK. Advise backup-code export first if the channels use different keys.
- Submit the recipe to [fdroiddata](https://gitlab.com/fdroid/fdroiddata), with `UpdateCheckMode: Tags` and `AutoUpdateMode: Version` so F-Droid detects future tagged releases. [Submission guide](https://f-droid.org/en/docs/Submitting_to_F-Droid_Quick_Start_Guide/)
